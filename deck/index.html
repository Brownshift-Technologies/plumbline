A plumb line is a weight on a string. It tells you what true vertical is, so you can see how far you have drifted.

A bug that is in production right now

  1. A customer buys something.
  2. The payment provider is slow that morning.
  3. The app retries the charge.
  4. The retry sends a new idempotency key instead of reusing the old one.
The customer is charged twice.

Support ticket. Refund. Chargeback fee. And an engineer spending a day proving it was the retry, not the provider.

Why no test caught it

It only happens when the provider is slow.

Writing a test that makes a provider slow on purpose is tedious.

So it gets pushed to next sprint. Every sprint.

240ms The latency nobody simulates. The provider's own p99 is 210ms, so the slow path is real, reachable, and untested.

Every team writes the happy path. The failure paths are where the money is, and they are the ones that never get written.

The suite rots

Written by hand against an interface that changes every sprint, faster than anyone can repair it.

The failure paths stay empty

Latency, timeouts, partial writes, toxic input. Tedious to simulate, so nobody does.

Root-causing eats a day

And the fix still needs a review from someone who was not there when it broke.

It is not that teams do not test. It is that the happy path is the only path anyone writes.

What everyone else is building

An agent that can write a test can write any file.

An agent that can open a pull request can merge one.

A tool description from someone else's server is text a stranger wrote that ends up in your prompt.

Whether a model can find a bug stopped being the interesting question. The question is what it is allowed to do the second it finds one.

What we build instead

One gate. Every tool call from every agent goes through a single function. There is no second path.

Deny by default. Scopes live in code, not in a customer setting.

Prove it afterwards. Every decision is hash-chained and independently verifiable.

Nothing bypasses it
